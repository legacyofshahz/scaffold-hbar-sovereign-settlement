# Scaffold-HBAR Bounty Campaign

## Primary objective

Clear the mechanical eligibility gate with one high-quality, differentiated template before spending effort on additional entries.

## Scoring target (aspirational, not a judge score)

- Ecosystem integration (35): Supra is load-bearing in the settlement policy.
- Documentation (30): README + AGENTS + environment + architecture + failure semantics.
- Code quality (20): bounded contract, EIP-712, custom errors, replay prevention, tests, CI, deterministic self-check.
- Hedera depth (15): Smart Contract Service + HCS + Mirror Node composition.

## Prize-pool strategy

The official brief has five $2,000 prizes and allows multiple submissions. It does not explicitly state that a single entrant can win all five. Therefore $10,000 is treated as a campaign ceiling, not an expected or guaranteed payout.

Only after the primary template passes cleanly should additional differentiated templates be considered. Reusing the same code with cosmetic changes is prohibited by our own quality bar.

Possible later derivatives, only if time and rules support them:

1. HTS guarded treasury / allowance settlement.
2. HSS scheduled guarded settlement.
3. Axelar cross-chain guarded settlement.
4. x402 receipt + HCS settlement evidence.

Each must have a genuinely different load-bearing integration and its own testnet proof.

## Survival constraint

Bounty winners are announced after judging, so this opportunity cannot be counted as immediate cash runway. Continue short-horizon opportunity discovery in parallel. Projected prize value is not realized wealth.
